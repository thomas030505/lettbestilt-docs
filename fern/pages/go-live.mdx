---
title: Go-live checklist
subtitle: Check these before real customers order
---

Work through this list with LettBestilt before you launch a restaurant's site.

Build and test against a sandbox first: it takes test orders and simulated online payments, and sends webhooks like a real restaurant. See [From sandbox to live](/sandbox-to-live).

<Warning>
With a live key, every order you create is a real order for the restaurant. Plan any tests on the real restaurant with the restaurant. Online orders that are never paid do not reach the kitchen.
</Warning>

## Access

- [ ] **The restaurant is live in LettBestilt.** The owner signs the agreements. LettBestilt approves the restaurant before the owner sets it live; you ask for the approval in LettBestilt Partner (the partner portal). Until the restaurant is live, every endpoint that takes a slug responds `404 RESTAURANT_NOT_FOUND`, except `GET /site-gate`. See [From sandbox to live](/sandbox-to-live).
- [ ] **The site uses the live key (`lbs_live_…`) and the real slug**, not the sandbox's test key and slug.
- [ ] **The API key is on your server only**, in an environment variable. It is not in browser code, a mobile app or a repository. The same goes for your partner key.
- [ ] **The key has the scopes the site needs.** A key limited to some scopes gives `403 INSUFFICIENT_SCOPE` on anything else. If it has an expiry date, a rotation is planned before it.
- [ ] **Every hostname is verified.** Add and verify each domain your site runs on, on the restaurant's **Domains** tab in the partner portal or with the LettBestilt Partner API, both `example.no` and `www.example.no` if you use both. Browser calls and payment return URLs only work from verified `https` domains.
- [ ] **All calls go to `https://www.lettbestilt.no/api/v1`.** The bare domain redirects, and the redirect drops the `Authorization` header.

## Checkout

- [ ] **The UI follows `restaurant.capabilities`.** Pickup, delivery, reservations, online payment and cash are only offered when they are `true`.
- [ ] **Ordering is gated on `restaurant.openingHours`**, the kitchen's hours, not on `venueHours`.
- [ ] **"Ready in about X minutes" comes from `GET /prep-time`**, so rush mode shows.
- [ ] **`successUrl` and `cancelUrl` are on a verified domain**, and `successUrl` contains `{TOKEN}`.
- [ ] **Every checkout attempt has its own `Idempotency-Key`**, and retries reuse it.
- [ ] **You send `expectedTotal`** and handle `409 PRICE_CHANGED` by showing the new total.
- [ ] **Your confirmation page checks `order.status`** with `GET /orders/{token}`, and does not treat the return to `successUrl` as proof of payment.
- [ ] **Your site serves `/order/{publicToken}`.** LettBestilt's order emails link to that path on the restaurant's website domain.
- [ ] **Stock photos are labelled.** When `product.imageIsStock` is `true`, show "Illustrasjonsfoto" next to the image.

## Webhooks

- [ ] **Your endpoint is public `https`** and registered for the real restaurant with the events you need. Sandbox webhooks do not carry over.
- [ ] **A test event arrives and verifies.** Use **Send test event** in the partner portal and check the delivery log.
- [ ] **The signature is verified** over the raw body, and old timestamps are rejected. See [Webhooks](/webhooks).
- [ ] **You answer `2xx` within 5 seconds** and do slow work afterwards.
- [ ] **Duplicates are skipped** using `X-LettBestilt-Delivery-Id`.

## Errors and limits

- [ ] **You branch on `error.code`**, and show `error.message` to the customer where it makes sense.
- [ ] **`429` waits for `Retry-After`**, and network errors retry with the same `Idempotency-Key`.
- [ ] **A `503` on order creation** lets the customer try again or choose cash.
- [ ] **The menu is cached on your side** and fetched with `If-None-Match`, so you do not refetch it for every page view.
- [ ] **You know your rate limits.** Server-side calls share your server's IP, which allows 10 orders per minute per restaurant. See [rate limits](/errors#rate-limits).

## Launch

- [ ] **If the site uses a password gate during preview**, it reads `GET /site-gate` from the server, so LettBestilt can turn the gate off at launch without a redeploy.
- [ ] **Check integration is green** in the restaurant's API section in the partner portal. See [Debugging with request IDs](/debugging).
- [ ] **One real order end to end**: menu, cart, payment, confirmation page, status updates and webhooks, agreed with the restaurant.
